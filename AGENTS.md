# Egebit Web

- Публичный репозиторий содержит только статический интерфейс. Никаких .env, ключей, базы, пользовательских условий, личных ссылок входа или отчётов с данными участников.
- Рабочий API и бизнес-логика находятся в соседнем Egebit/egebit/web.py и используют существующие очередь, квоты, шаблоны и sandbox. Не создавайте независимую очередь или обход бюджета.
- Вход через персональный /web в группе. Никакого доверия к переданному клиентом Telegram ID или признаку администратора.
- С 19.10.2026 решение доступно без входа: автоматически создать /api/guest, хранить отдельный токен в localStorage. Чужие заявки и админка закрыты сервером. После /web — история Telegram и публикация в группе; гостевые условия и ответы остаются в браузере. Не смешивать эти пояснения.
- Без лишних декоративных слоганов. Номера шагов/карточек — 1, 2, без ведущих нулей. Исходные ID задач и даты не менять.
- Отображайте реальный статус. Код из результатов рендерится как текст, а не HTML. Не выполняйте Python/HTML из файлов пользователя.
- Публикация GitHub Pages: veylcode/egebit, main, корень. Сохраняйте текущий origin/API и мобильную раскладку.

- С 2.5.0 есть отдельные регистрация и вход по логину/паролю. Telegram /web не менять. 15 задач/5 часов на ключ браузера; без IP-квоты и отдельного гостевого бюджета. Никаких клиентских назначений admin. Гостевой device principal отличается от аккаунта, после выхода история аккаунта закрыта. Хранить токены Telegram, аккаунта и устройства отдельно. APInex отключён.
- С 2.6.0 новая отправка идёт через /api/previews и подтверждение /api/jobs/ID/confirm. До подтверждения не запускать решение и не публиковать условие в группе. Не затирать редактируемый предпросмотр опросом статуса. До 5 файлов по 4 МиБ, до 16 МиБ вместе; страницы одного условия включаются отдельно. До 50 условий/32000 символов суммарно.
- features.js загружается defer перед app.js; общие bindings используются после инициализации приложения. Сохранять разграничение токенов при асинхронной загрузке подборок/жалоб. Результаты, условия и названия подборок выводить только с экранированием. Жалобы доступны владельцу через API, не через клиентское назначение роли. Лимит задач и общий расчётный API-бюджет — разные показатели; последний не равен балансу Яндекса.
- PWA 2.7.0: sw.js кэширует только точный allowlist статических файлов в scope проекта. Никогда не кэшировать API, Bearer, ZIP, пользовательские условия/ответы; не менять вход/квоты. Не перезагружать незавершённую форму ради обновления без явного нажатия пользователя. Согласованно менять версии HTML/assets и shell-cache. ZIP берётся через авторизованный POST /api/library/export и текущий фильтр темы, а не через публичную ссылку с токеном.
- 2.8.0: денежный блок удалён с главной. Обычные пользователи не получают суммы/тарифы/финансовые причины даже в /api/me и истории ошибок. Публичный GET /api/status содержит только короткий статус и время проверки; polling 15 секунд, ошибка сети немедленно убирает зелёный статус. Детальная диагностика и расходы — только owner admin. Не обещать работу платного ИИ при реальном исчерпании общего лимита и не подменять проверку соединения проверкой генерации. Последние заявки без разрешения владельца не повторять; общий предел 100 ₽ не менять.
